راهنمای کامل پنل WhitePrivateDns

این راهنما برای مدیر سرور است. نام دکمه‌ها مطابق پنل انگلیسی نوشته شده‌اند. example.com و 203.0.113.10 فقط نمونه هستند؛ آن‌ها را عیناً در تنظیمات واقعی وارد نکنید. دسترسی را از شبکهٔ یک مشترک واقعی هم آزمایش کنید؛ آزمون روی خود VPS کافی نیست.

ترتیب راه‌اندازی

  1. سرویس را با راهنمای نصب نصب کنید. دامنهٔ پنل و گواهی HTTPS باید سالم باشند. پورت پنل را از خروجی نصب بردارید؛ آن را ۸۰۸۰ فرض نکنید. برای نصب موجود، از راهنمای به‌روزرسانی استفاده کنید.
  2. نام کاربری، رمز و مسیر مخفی پنل را ذخیره و 2FA را فعال کنید.
  3. وضعیت upstreamها را در Overview بررسی کنید. یک حساب آزمایشی در Clients بسازید و IP واقعی دستگاه را ثبت کنید.
  4. دستگاه را طبق Connect guide وصل کنید؛ در Live queries، دامنه، قاعده و تصمیم DNS را ببینید.
  5. برای DoH پشت CDN/Tunnel، اول مسیر بیرونی را راه‌اندازی و آزمایش کنید، بعد Public DoH URL را ثبت کنید.

Clients و ساخت مشترک

Client Access Whitelist Mode وقتی روشن است، IP ثبت‌نشده را از DNS و مسیرهای بازی محروم می‌کند. پیش از دادن تنظیمات به مشترک، حساب و IP او را ثبت کنید. کادر جست‌وجو نام، شناسه یا IP را پیدا می‌کند. Add New Client بالای فهرست، کنار جست‌وجو است.

در کارت DNS access mode، عدد Private-mode DNS refusals since restart نشان می‌دهد چند درخواست واقعاً به همین سرور رسیده و به‌خاطر IP ثبت‌نشده رد شده است. پیش از آزمون، عدد Total queries در Overview را یادداشت کنید؛ سپس از همان شبکه و همان اپ کلاینت چند درخواست بفرستید. اگر Total queries تغییر نکند، ترافیک به این فرایند نمی‌رسد یا DNS دیگری پاسخ می‌دهد؛ اگر Total queries و شمار ردشدن بالا بروند، ردیف‌های REFUSED در Live queries را برای IP مبدأ بررسی و با IP ثبت‌شده مقایسه کنید. این ردیف‌ها برای جلوگیری از سیل لاگ نمونه‌برداری می‌شوند و ممکن است هر درخواست را نشان ندهند. صفر بودن شمار ردشدن به‌تنهایی سالم بودن مسیر را ثابت نمی‌کند. در حالت عمومی DNS برای همه باز است، ولی رلهٔ ناشناس فقط دامنه‌های PROXY فعال را می‌پذیرد و سهمیهٔ اختصاصی ندارد.

بعد از ساخت، Subscription Link و Registration Secret را فقط به همان مشترک بدهید. لینک پورتال برای نمایش اطلاعات است؛ تغییر IP به رمز ثبت جداگانه نیاز دارد. رمز را در اسکرین‌شات یا مخزن عمومی منتشر نکنید. اگر IP کاربر عوض شد، او باید آن را دوباره ثبت کند یا مدیر در Edit Client → Manual IP Address تغییر دهد. فرم ویرایش نام، سهمیه، دورهٔ بازنشانی، انقضا، یادداشت و سیاست‌ها را هم دارد. UUID یا رمز ثبت را فقط در صورت نیاز تغییر دهید، چون لینک‌ها/دسترسی قبلی ممکن است از کار بیفتند.

Policies

Quick Policy Profiles چند سیاست را یکجا فعال می‌کنند: Pro Gamer، Streamer، Dev 403 و Safe DNS. کارت‌های Gaming، Streaming/Media و Developer/Security نیز جداگانه روشن و خاموش می‌شوند. این نام‌ها تضمین رفع تحریم یا کاهش پینگ همهٔ بازی‌ها نیستند؛ هر تغییر را با درخواست واقعی و ستون‌های RULE MATCHED و ACTION در Live queries بررسی کنید. اگر سرویس خراب شد، همان سیاست را برگردانید. رله‌کردن دانلود حجیم می‌تواند CPU و پهنای باند زیادی مصرف کند؛ فقط در صورت نیاز فعالش کنید.

کنترلچه بگذاریم؟نتیجهٔ ذخیره
Active relay IPv4IPv4 عمومی که به همین VPS اختصاص دارد و رلهٔ SNI روی آن برای مشترک قابل‌دسترسی است. با یک IP سالم، مقدار فعلی را تغییر ندهید.Apply relay address آدرس پاسخ‌های جدید دامنه‌های PROXY را عوض می‌کند. اتصال‌های باز مسیر قبلی را نگه می‌دارند؛ کش دستگاه ممکن است پاسخ قدیمی را تا حدود ۶۰ ثانیه نگه دارد.

مقادیر تصویر شما

  • عدد داخل Active relay IPv4 مقدار فعلی نمایشی است؛ از خود تصویر نمی‌توان مالکیت یا سلامت آن را تأیید کرد. اگر IP عمومی همان VPS است و رله از شبکهٔ مشترک باز می‌شود، آن را نگه دارید. IP کلادفلر، سرور دوم، IP خصوصی یا IPی که صرفاً رکورد دامنه به آن اشاره دارد را در این فیلد وارد نکنید. این دکمه IP سیستم‌عامل، فایروال یا سرور دوم را پیکربندی نمی‌کند.
  • https://doh.example.com/dns-query فقط متن نمونهٔ داخل کادر است، نه URL فعال. example.com را عیناً ذخیره نکنید. بدون مسیر بیرونی آماده، فیلد را خالی بگذارید.
  • URL عمومی باید https://، میزبان واقعی و مسیر دقیق /dns-query داشته باشد. این فیلد URL با نام کاربری/رمز، query مانند ?token=... یا fragment را نمی‌پذیرد. اگر DoH توکن می‌خواهد، آن را جداگانه طبق تنظیمات دسترسی به مشترک مجاز بدهید.

راه‌اندازی DoH پشت Cloudflare Tunnel

  1. DoH محلی و گواهی معتبر را در SSL / TLS Manager → DNS TRANSPORTS آماده کنید. URL مستقیم معمولاً https://نام-دامنه:8443/dns-query است.
  2. یک Published application برای doh.your-domain.tld بسازید که به DoH محلی همان سرور، مثلاً https://127.0.0.1:8443، برسد. اگر گواهی مبدأ برای dot.your-domain.tld صادر شده، Origin Server Name را همان نام گواهی بگذارید و اعتبارسنجی TLS مبدأ را روشن نگه دارید. راهنمای رسمی Tunnel و مبدأ HTTPS.
  3. کش اشتراکی، Challenge/CAPTCHA و صفحهٔ ورود مرورگری را برای /dns-query مستثنا کنید؛ کلاینت DNS باید پاسخ DoH واقعی بگیرد. این تنظیم در Cloudflare انجام می‌شود.
  4. از اینترنت مشترک URL نهایی را با scripts/network_probe.py یا یک کلاینت DoH آزمایش کنید. HTTP 200 به‌تنهایی کافی نیست؛ پاسخ DNS معتبر لازم است. بعد از موفقیت URL را در Public DoH URL ذخیره کنید.
  5. در Connect guide → Browser Secure DNS (DoH) URL جدید را کنترل کنید. اگر خراب بود، فیلد را پاک و ذخیره کنید تا URL مستقیم برگردد.

فقط HTTP(S) مربوط به DoH از این Tunnel می‌گذرد. DNS عادی روی UDP/TCP 53، Android Private DNS/DoT روی 853، و TCP رلهٔ SNI مسیرهای مستقلی هستند. رکورد نارنجی معمول Cloudflare آن پروتکل‌ها را به سرور شما منتقل نمی‌کند. WARP نیز با این دو فیلد راه‌اندازی نمی‌شود و مدیریت سمت کاربر می‌خواهد. انتخاب سالم‌ترین IP و همگام‌سازی چند سرور خودکار نیست. پورت‌های قابل‌پروکسی Cloudflare و راهنمای مسیرهای پایدار پروژه را ببینید.

سایر بخش‌های Settings

کارت / فیلدچه مقدار و چه اثری؟
Two-Factor Authenticationرمز فعلی را وارد و Start Enrollment بزنید. کلید نمایش‌داده‌شده را در برنامهٔ TOTP ذخیره کنید؛ برای Confirm & Enable دوباره رمز فعلی و کد ۶ رقمی را وارد کنید. کلید را خصوصی نگه دارید. غیرفعال‌سازی به رمز و کد نیاز دارد و همهٔ نشست‌ها را خارج می‌کند.
LDAP Directory Loginفقط اگر Active Directory/OpenLDAP دارید: ldaps://host:636، Bind DN، Bind password، Base DN و User attribute (پیش‌فرض uid) را مطابق دایرکتوری پر کنید. حالت Local login only، LDAP only یا LDAP with local fallback را آگاهانه برگزینید؛ قبل از حذف راه ورود محلی، LDAP را آزمایش کنید. ذخیره به رمز فعلی مدیر و در صورت فعال‌بودن 2FA به کد نیاز دارد و نشست‌ها را خارج می‌کند. Bind password خالی هنگام ویرایش یعنی حفظ رمز قبلی.
Hidden Admin Pathمسیر فعلی را برای بوکمارک و API نگه دارید. Regenerate Path لینک‌ها و نشست‌های قبلی را فوراً بی‌اعتبار می‌کند. مسیر مخفی جای رمز و 2FA نیست.
Subscription PortalPortal enabled صفحات مشترک را فعال می‌کند. Subscription domain فقط نامی باشد که واقعاً به سرور می‌رسد؛ خالی یعنی دامنهٔ پنل. Advertised port باید از بیرون باز باشد؛ پورت متفاوت listener جدا باز می‌کند و در فایروال میزبان و ارائه‌دهنده نیز باید مجاز شود. Portal title عنوان دلخواه است. برای دامنهٔ مستقل با Let's Encrypt گواهی بگیرید، Save Subscription Settings را بزنید و لینک یک حساب آزمایشی را باز کنید.
Administrator Credentialsبا Change Username / Password نام/رمز مدیر را عوض کنید. رمز طولانی و یکتا بگذارید؛ تغییر رمز نشست‌های دیگر را خارج می‌کند.
SSL / TLS Manager → DNS TRANSPORTSنام واقعی DoT/DoH مثل dot.your-domain.tld را وارد و Let's Encrypt را بزنید؛ خالی یعنی دامنهٔ پنل. Android Private DNS فقط نام میزبان می‌خواهد، بدون https://، پورت یا مسیر. DoT روی 853 و DoH محلی روی 8443 است.
SSL / TLS Manager → ADMIN PANELنام خود داشبورد را وارد کنید؛ این فیلد برای تغییر نام DoT/DoH نیست. ایمیل تماس گواهی اختیاری است. تغییر نام روی لینک پنل و گواهی مدیر اثر می‌گذارد؛ DNS و دسترسی HTTPS را پیش از صدور بررسی کنید.
Custom Proxied Domainsنام دقیق مثل api.your-service.tld یا الگوی پشتیبانی‌شده مثل *.your-service.tld را وارد و Add کنید. پاسخ DNS این نام به IP رله می‌رود؛ اول با یک نام مشخص آزمایش کنید.
Custom Blocklist (Sinkhole)نامی را که باید مسدود شود وارد و Block کنید؛ پاسخ مسدودشده می‌تواند 0.0.0.0 باشد. مراقب دامنه‌های مشترک چند سرویس باشید.
DoH Secret Tokensتوکن طولانی و تصادفی بسازید و Add Token کنید. هنگام فعال‌بودن این کنترل، کلاینت باید ?token=... را با درخواست DoH بفرستد. توکن را فقط به مشترک مجاز بدهید.
Custom Static Recordsیک hostname و IP معتبر A/AAAA وارد و Save کنید. رکورد ثابت پاسخ DNS همان نام را عوض می‌کند؛ IP اشتباه سرویس را قطع می‌کند.
Dashboard Session Idle Timeoutعددی بین ۵ و ۱۴۴۰ دقیقه وارد و Save کنید. نشست پس از این مدت بی‌فعالیتی باطل می‌شود؛ عمر مطلق آن ۲۴ ساعت است.

قانون دستی باید نام میزبان معتبر با پسوند دامنه باشد؛ *.example.com فقط زیردامنه‌ها را پوشش می‌دهد، پس اگر خود example.com هم لازم است آن را جدا اضافه کنید. پنل قانون نامعتبر را رد می‌کند و در خطای ذخیره، تغییرات قبلی را دست‌نخورده نگه می‌دارد. افزودن دامنه فقط مسیر DNS و TCP با SNI/Host را عوض می‌کند؛ برای UDP بازی یا تونل کامل کاربرد ندارد.

API gateway و Connect guide

API gateway برای خودکارسازی ساخت حساب و مدیریت است. معمولاً اتصال API را روی 127.0.0.1 نگه دارید. Expose API to Public فقط وقتی لازم است روشن شود که دامنه و HTTPS معتبر دارید و دسترسی شبکه را محدود کرده‌اید. Master API Authentication Key دسترسی مدیریتی کامل می‌دهد؛ آن را فقط در محیط امن کپی کنید. Regenerate Key کلید قبلی و یکپارچه‌سازی‌های وابسته را از کار می‌اندازد. مسیر Interactive Swagger Docs و مرجع API قالب درخواست‌ها را نشان می‌دهند. نمونه‌کدهای پنل از 127.0.0.1:8080 به‌عنوان نمونه استفاده می‌کنند؛ آدرس و پورت واقعی API خود را جایگزین کنید.

دستگاهچه چیزی وارد کنیم؟
Windows 10/11 و PS5/XboxIP عمومی DNS سرور در تنظیمات IPv4 DNS. اگر لیست سفید فعال است، IP عمومی مبدأ کاربر نیز باید در حسابش ثبت شده باشد.
Android Private DNSفقط hostname معتبر DoT مانند dot.your-domain.tld؛ دسترسی به 853 و گواهی همان نام لازم است.
Browser Secure DNSURL کامل DoH با https:// و /dns-query. اگر Public DoH URL تنظیم شده، همین نشانی در راهنما نمایش داده می‌شود.

برای روتر یا iOS، منوی تنظیمات بسته به مدل و نسخه متفاوت است؛ اصل تنظیم همان IP DNS یا پروفایل DoH/DoT معتبر است. DNS ثانویهٔ نامربوط ممکن است باعث شود بخشی از درخواست‌ها اصلاً به WhitePrivateDns نرسد.

عیب‌یابی مسیرهای شبکه

از دستگاهی روی اپراتور مشترک آزمایش کنید؛ همهٔ نمونه‌ها را با مقادیر خود جایگزین کنید:

python3 scripts/network_probe.py \
  --dns-ip 203.0.113.10 \
  --dot-host dot.your-domain.tld \
  --doh-url https://doh.your-domain.tld/dns-query \
  --relay-ip 203.0.113.10 \
  --relay-sni your-proxied-domain.tld \
  --json

--relay-sni باید نامی باشد که واقعاً در Policies/Custom Proxied Domains به رله می‌رود. اگر DoH توکن دارد، متغیر WHITEPRIVATEDNS_DOH_TOKEN را برای ابزار تنظیم کنید. بازبودن پورت TCP به‌تنهایی سالم‌بودن رله یا پاسخ DNS را ثابت نمی‌کند. خرابی DoH را از خرابی DoT/53 و رله جدا کنید؛ تایم‌اوت در یک شبکه هم به‌تنهایی اثبات فیلترینگ نیست. آزمون دقیق چند مسیر و آموزش نصب و کاربری را ببینید.

برای مدیریت سرویس از ترمینال، روش کار با wpdns و تهیه/بازیابی پشتیبان در بخش‌های ۱۴ و ۱۵ آموزش گام‌به‌گام آمده است.
